# 实现与维护说明

## 运行边界

Android 宿主从 APK 读取本地页面，通过 `https://lulu.local/` 映射到 `assets/game/`。该地址只用于 WebView 的本地来源隔离，不需要 DNS 或服务器。宿主返回 HTML、JavaScript、CSS、PNG 与 JSON 对应的 MIME 类型，拦截其他请求；应用不申请网络权限。页面 CSP 允许同源读取两份资源清单。

`core.js` 负责固定时间步模拟、碰撞、道具、分数与动画选帧；`game.js` 负责画面、音频、输入和页面状态；Java 宿主负责全屏、安全区和生命周期。构建配置、SDK 与 APK 产出保持由现有 GitHub Actions 管理。

## 状态与记录

主页开始后进入运行状态，暂停后必须经过 3 秒倒数才恢复。失去焦点、隐藏页面、Android 切后台或倒数中断都返回暂停窗口；切换页面状态会清除未完成的手势。方向键及大小写 WASD 控制移动，长按 Esc 不重复触发暂停切换。

碰撞或主动结束本局时只结算一次。浏览器 `pagehide` 只暂停，避免页面从往返缓存恢复后仍继续游玩却无法记录新增进度。尚未结算的一局在刷新、关闭或系统杀进程后不保证恢复；已有结算记录和设置保存在 `lulu.run.v1`，存储不可用时游戏仍可进行并提示保存失败。

## 动画与内存

主页帧从 `pet/manifest.json` 读取，跑酷帧从 `runner/manifest.json` 读取。文件顺序、坐标基准、画布尺寸和动作时间参数不在绘制代码中重复保存。

- `strideMeters`：完整跑步循环对应的前进距离，因此加速会自然提高步频，暂停时动作冻结。
- `phaseEnds.jump` / `phaseEnds.slide`：各帧在完整动作中结束的比例，严格递增且末项为 1。低姿滑行的中段保留较长显示时间。
- `anchorX` / `anchorY`：画布中的角色定位基准，不一定等于每帧最低像素。跳跃高度由逻辑层控制，不额外拉伸图片。
- `bounds`、SHA-256 和 PNG 校验用于检查资源是否被替换、损坏或裁掉边缘，不能代替人工检查动作质量。

资源准备完成前禁用开始按钮，显示完成帧数；清单或单张图片加载超过 15 秒会失败并提供重新加载入口。图片使用两个解码任务，每帧建立 512 × 512 Canvas 绘制缓存，随后释放代码对源图片的引用。28 张缓存的理论像素容量共 28 MiB，原尺寸图片直接常驻时约 108 MiB；浏览器仍可能保留解码缓存和 GPU 副本，这些数字不是进程峰值内存测量。

## 修改与验证

修改逻辑或资源后执行 `npm run check` 和 `npm test`，无需安装 npm 依赖。资源检查使用 Python 标准库校验透明 PNG、清单和本地文档链接。替换动画时先更新资源来源、提示词和清单，再验证全部动作切换。

`python3 scripts/check_browser.py` 是可选的真实 Firefox 页面检查，使用已安装 Firefox / geckodriver，运行本地临时 HTTP 服务。检查加载、开始、跳跃、滑行、暂停、恢复中断、结算、重新开始、设置保存和窄屏界面；退出时关闭服务和浏览器，截图与日志保留在 `/tmp/lulur-run-browser-*` 供复核。Firefox 结果不能证明 Android WebView 兼容性。

正式验证仍以 CI 的 Android lint、APK 构建与[真机验收](ANDROID_ACCEPTANCE.md)为准。项目不自动提交、推送或发布，也不为验证安装 SDK 或浏览器。
